 --------------------scenarios.json
Це вхідні дані для generate.py.

НАВІЩО КОМІТИТИ: Без нього система не знатиме, які саме ситуації потрібно змоделювати.

ЯК ПРАЦЮЄ: Скрипт зчитує цей JSON і використовує initial_client_prompt
та agent_specific_instructions як інструкції для генерації діалогу через LLM

КЛЮЧОВІ ПОЛЯ:

case_id: ID сценарію.

expected_client_satisfaction: Очікуваний результат (еталон). 
Використовуйте для порівняння з реальним результатом аналізу.

Важливо (Кейс CS009): Спеціальний сценарій для перевірки "прихованою незадоволеності". 
Навіть якщо клієнт каже "Дякую", очікуваний статус — unsatisfied.

----------------------eval_configs.json
Є інструментарієм для analyze.py.

НАВІЩО КОМІТИТИ: Це "інтелект" аналізатора. У ньому прописано, за якими критеріями
оцінювати задоволеність (satisfaction) та якість роботи агента (quality_score).

ЯК ПРАЦЮЄ: Скрипт підтягує system_prompt та user_prompt_template для кожного чату,
щоб отримати структурований JSON-аналіз.

КЛЮЧОВІ ПОЛЯ:

id: Унікальний ідентифікатор завдання (наприклад, customer_satisfaction_v1). 
Використовуйте його в коді для виклику конкретного аналізу.

system_prompt: Роль, яку приймає ШІ (наприклад, "Ти — спеціаліст з контролю якості").

expected_output_format: Формат, у якому ШІ має повернути відповідь.
